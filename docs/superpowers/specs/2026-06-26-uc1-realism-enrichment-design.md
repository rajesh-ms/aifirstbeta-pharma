# UC1 Discovery Orchestration — Realism Enrichment (Design Spec)

**Date:** 2026-06-26
**Status:** Approved (brainstorm) → ready for implementation plan
**Builds on:** `2026-06-25-uc1-discovery-orchestration-demo-design.md` and the shipped app under `demo/uc1-discovery-orchestration/`.

## 1. Problem

The demo reads as "fabricated" to a scientific/leadership audience: generic candidate IDs, textbook-only framework sequences, round metrics with no method, and "REAL · Azure" payloads with no run metadata, sources, or audit trail. The biology and headline numbers are sound but lack **provenance and specificity**.

## 2. Goal

Make the demo **credibly real through authenticity and provenance** — real, verifiable identifiers; named predictors; richer (clearly *predicted*) metrics; run metadata on the two live calls; a clickable Sources panel; and a governed audit trail — **without** wiring a live data backend, and **without** dressing up simulated outputs as genuine experimental/clinical results.

### Integrity guardrails (non-negotiable)
- Live-vs-simulated labels stay; all model-derived metrics are tagged **"predicted"**.
- Candidate sequences are labeled **"de novo generated (synthetic)"** — honest, since they are AI-designed novel antibodies.
- **Citations are curated and verified** from public sources, **not** generated by the LLM (avoids hallucinated references — and is itself a governance selling point: grounded retrieval, curated evidence).
- Only Stage 1 (Target ID) and Stage 5 (Rank) make real Azure calls; everything else stays simulated.
- The Azure key never reaches the browser (unchanged).

## 4. Data model changes (fixtures)

### 4.1 `scenario-pvrig.json`
Add (speed math unchanged):
- `program.targetRefs`: `{ uniprot:"Q6DKI7", pdb:"8X6B", ligand:"CD112 / Nectin-2 (Q92692)", axis:"DNAM-1 / TIGIT" }`
- `program.market`: `{ drug:"Keytruda (pembrolizumab)", fy2024RevenueUsdB:29.5, shareOfPharmaPct:46, usLoeYear:2028, citation:"Merck FY2024 results" }`
- Each `stages[]` entry gains `methods: string[]` (named predictors + versions) and `dataSources: string[]`.
- Top-level `references: [{label, url}]` — the curated Sources list (drives the UI panel).

### 4.2 `candidates.json`
Each candidate gains:
- `format` (split from name: "IgG1"/"IgG4"), `germline: {vh,jh,vl,jl}` (e.g. `IGHV3-23/IGHJ4`), `cdrh3` (string), keep `sequenceSnippet` but document it is generated.
- `metrics`: `{ kdNm, kdMethod:"predicted SPR-equivalent", tmC, pI, hmwPct, developabilityScore, interfaceScore, immunogenicity:{score,method:"NetMHCII/IEDB",highRiskEpitopes}, tapFlags:[] }`
- `liabilities: [{motif,type,region,pos,severity}]` (replaces flat `toxFlags`; e.g. `{motif:"NG",type:"deamidation",region:"CDR-H2",pos:55,severity:"low"}`)
- `predictedBy: string[]` (tools that produced the metrics)
- keep `triageStatus`, `stage4Reason`.

### 4.3 `canned-stage1.json` (Target ID)
- Sharpen `target.mechanism` to verified biology (ligand CD112/Nectin-2; DNAM-1/TIGIT axis; blocking PVRIG restores CD226-mediated NK/T cytotoxicity, complementary to PD-1).
- `target.citations: [{label,url}]` (UniProt, PDB, NCT, market).
- `provenance` block (see §5).

### 4.4 `canned-stage5.json` (Rank)
- Each ranking entry gains `scores: {affinity,developability,immunogenicity,manufacturability}` and `method:"multi-objective weighted (predicted)"`.
- `overallRecommendation`: replace reg ref (§6).
- `provenance` block (see §5).

## 5. Run-metadata (provenance) — server-attached, fixture-mirrored

Shape (on Stage 1 & 5 responses):
```json
"provenance": {
  "model": "gpt-4o", "deployment": "<AZURE_OPENAI_DEPLOYMENT>", "apiVersion": "2024-10-21",
  "promptTemplate": "target-id@v1.3", "promptHash": "sha256:…",
  "temperature": 0.2, "seed": 7,
  "tokens": { "prompt": 0, "completion": 0, "total": 0 },
  "latencyMs": 0, "requestId": "<uuid>", "timestamp": "<ISO>",
  "grounding": "retrieval over curated PVRIG evidence pack",
  "mode": "live"
}
```
- **Live mode (server):** `server.js` fills `model/deployment/apiVersion` from config, `tokens` from the Azure `usage` field, `latencyMs` measured, `requestId`=uuid, `timestamp`=now. `promptTemplate/promptHash/temperature/seed/grounding` are config constants.
- **Simulated mode:** canned fixtures carry a representative `provenance` with `mode:"simulated"`; the client keeps its existing `mode:'simulated'` tagging.

## 7. UI changes (`index.html`, `app.js`, `theme.css`)

New element IDs are the contract for tests:
- **Sources panel** `#sources` — renders `scenario.references` + collected `citations[]` as clickable `<a target="_blank" rel="noopener">`. Visible in both lenses (compact in executive, full in technical). Each candidate/target/stage links resolve to real public URLs.
- **Run-metadata strip** in the technical lens near the Stage 1/5 payloads (`#provenance-stage1`, `#provenance-stage5`): model · api-version · tokens · latency · requestId(short) · timestamp · promptTemplate.
- **Richer candidate card** in the shortlist (`.shortlist .row`): name + format, germline (VH/JH), CDR-H3 (monospace), metric chips (KD, Tm, %HMW, immunogenicity), liability badges. All values HTML-escaped (existing `esc()`).
- **Audit trail** at the gate (`#audit`): one entry per gate action — `actor · role · action · reason · ISO timestamp · hash` — hash-chained for tamper-evidence (illustrative digest of `prev_hash + entry`, e.g. SubtleCrypto SHA-256 truncated, or a short synchronous hash); reg refs corrected.

All new live-derived strings continue through `esc()` (XSS fix preserved).

## 8. Out of scope (explicit)

- No live external data fetching (UniProt/PDB/ChEMBL API calls) — sources are clickable links only.
- No third real Azure call (send-back stays a canned simulated re-rank).
- Speed math, fallback contract, and two-step gate flow unchanged.
